
# Case Study 33: Online Portfolio Builder

## 1. Problem Statement

Students need a simple platform to showcase their projects, technical skills, certificates, and achievements. Creating and maintaining a personal portfolio can be difficult for students who do not have web development knowledge. The Online Portfolio Builder allows students to create and share professional portfolios easily.

## 2. Product Backlog

| ID | User Story | Priority |
|---|---|---|
| PBI-1 | As a student, I want to register and log in. | High |
| PBI-2 | As a student, I want to create my profile. | High |
| PBI-3 | As a student, I want to add my skills and achievements. | High |
| PBI-4 | As a student, I want to upload project details. | High |
| PBI-5 | As a student, I want to add certificates. | Medium |
| PBI-6 | As a student, I want to share my portfolio link. | Medium |
| PBI-7 | As a student, I want to customize the portfolio design. | Low |

## 3. Sprint Plan

### Sprint 1
- Student registration and login
- Create and edit student profiles
- Add skills and achievements

### Sprint 2
- Add project details and certificates
- Customize portfolio layout
- Generate and share a portfolio link
- Test the application

## 4. Sprint Backlog

**Sprint 1 Tasks**
- Design the registration and login pages.
- Implement student authentication.
- Create the profile form.
- Add fields for skills and achievements.
- Test profile creation and editing.

**Sprint 2 Tasks**
- Develop the project details section.
- Add certificate information.
- Create portfolio templates.
- Implement portfolio link sharing.
- Test the complete application.

## 5. Increment

**Sprint 1 Increment:** Students can register, log in, create profiles, and add skills and achievements.

**Sprint 2 Increment:** Students can add projects and certificates, customize their portfolios, and share their portfolio links.

## 6. Sprint Review

The team demonstrates the portfolio creation features to students and stakeholders. Feedback is collected about profile editing, design customization, and portfolio sharing. Improvements are added to the product backlog.

## 7. Sprint Retrospective

**What went well:** The team divided the features into two manageable sprints and prioritized essential student profile features.

**What could be improved:** Portfolio layouts and mobile compatibility require more testing.

**Action for improvement:** Improve usability testing, communicate regularly, and prioritize student feedback in future sprints.

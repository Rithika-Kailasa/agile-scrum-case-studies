
# Case Study 31: Food Wastage Reduction App

## 1. Problem Statement
Restaurants often have excess food, while NGOs need food to support people in need. This application connects restaurants with NGOs so that surplus food can be donated instead of wasted.

## 2. Product Backlog

| ID | User Story | Priority |
|---|---|---|
| PBI-1 | As a restaurant, I want to register and log in. | High |
| PBI-2 | As a restaurant, I want to list excess food. | High |
| PBI-3 | As an NGO, I want to view available food donations. | High |
| PBI-4 | As an NGO, I want to request food donations. | High |
| PBI-5 | As a restaurant, I want to confirm donation requests. | Medium |
| PBI-6 | As an NGO, I want to track food collection. | Medium |

## 3. Sprint Plan

### Sprint 1
- User registration and login
- Restaurant food listing
- NGO viewing available donations

### Sprint 2
- NGO donation requests
- Restaurant confirmation
- Food collection status tracking

## 4. Sprint Backlog

**Sprint 1 Tasks**
- Design the registration page.
- Implement login.
- Create the food listing form.
- Display available donations.

**Sprint 2 Tasks**
- Develop the donation request feature.
- Add request confirmation.
- Implement collection status.
- Test the application workflow.

## 5. Increment

**Sprint 1 Increment:** Users can register, restaurants can list surplus food, and NGOs can view available donations.

**Sprint 2 Increment:** NGOs can request food, restaurants can confirm requests, and users can track collection status.

## 6. Sprint Review

The team demonstrates the completed features to stakeholders. Feedback is collected to improve the food donation process.

## 7. Sprint Retrospective

**What went well:** Work was divided into manageable tasks and the core features were prioritized.

**What could be improved:** Food safety information and notifications need better planning.

**Action for improvement:** Improve testing, communication, and prioritization in the next sprint.
